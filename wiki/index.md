- [Can ALTER TABLE ... ATTACH PARTITION Drop Indexes in PostgreSQL 17? (unverified)](v17/questions/attach-partition-index-drops.md) - Answers that `ALTER TABLE ... ATTACH PARTITION` never drops an index from the table being attached: `AttachPartitionEnsureIndexes` is strictly match-or-create — for each partitioned parent index it re-parents a compatible existing partition index via `IndexSetParentIndex` (kept, not rebuilt) or creates a cloned one via `DefineIndex`, while incompatible/extra/invalid child indexes are left in place (regression-proven by the `indexing` test showing four incompatible indexes retained plus one added). Distinguishes the three look-alikes that are not ATTACH drops (a re-parented index becomes `relispartition` and can no longer be dropped on its own; the documented manual drop of the now-redundant CHECK constraint; a later cascading `DROP INDEX` on the parent). Includes a "changes since PostgreSQL 12" section: the no-drop invariant is unchanged, plus the invalid-index match skip (`indisvalid` guard, commit `fc55c7ff`, back-patched to v11+ so it post-dates the pinned 12.2), the v17-only same-constraint-type match that stops a PRIMARY KEY matching a plain UNIQUE (commit `cee8db3f`), and mechanical attmap / `DefineIndex` `total_parts` / `foreach_oid` refactors — anchored to the v17 checkout's source and commit history.
